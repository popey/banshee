# Desktop integration comparison with Banshee 2.9.1

Compared the official 2.9.1 source snapshot while restoring desktop integration
in the working 2.6.2 snap. This is a source comparison, not a 2.9.1 build or
runtime validation.

Source: https://download.gnome.org/sources/banshee/2.9/banshee-2.9.1.tar.xz
SHA-256: `35d41f9632b93da742440ac2bce4e3dbac7049b4c9b56348ba7eb18afe60276d`

- All MPRIS C# files are identical between the two official releases. Restoring
  their runtime dependency and snap interfaces does not require inventing a
  separate MPRIS implementation for 2.6.2.
- Both request dbus-sharp-1.0 >= 0.7 and use the same obsolete three-argument
  Connection.Register overload. Ubuntu's dbus-sharp 0.8.1 (2.0 ABI) passed a
  confined session-bus test where 0.7 failed with MethodAccessException.
  `dbus-sharp2.patch` applies to both source trees, including enabling MPRIS
  by default. The separate `mpris-snap-desktop-entry.patch` also applies to
  both and advertises the installed snap desktop entry to GNOME.
- 2.9.1 fixes the disabled-D-Bus startup path and reorganizes initialization.
  The existing `respect-disable-dbus.patch` should not be blindly carried over.
- 2.9.1 removes the custom X11 tray backend and can omit its GTK status icon
  when the notification server supports persistence. It does not include an
  AppIndicator implementation. Its GTK3 changes mean the Ayatana adapter needs
  a reviewed port, using the GTK3 Ayatana library rather than the GTK2 library.
- The snap library-path and podcast recovery patches apply textually to 2.9.1.
  This is encouraging but does not prove they are necessary or correct there.
  The GTK file-chooser patch also applies textually, but GTK3 marshalling and
  the actual chooser backend must be reassessed before retaining it.
- `modern-mono.patch` requires reassessment; it combines compilation and
  distribution-patch compatibility changes that may be unnecessary on 2.9.1.

Keep the working 2.6.2 snap and its regression tests while evaluating 2.9.1 in
a separate build. Reuse the CA trust, confinement, and runtime-path work where
appropriate; audit the Ubuntu patch series instead of applying it wholesale.

The later Last.fm account test also found that `Banshee.Web/Browser.cs` is
identical in 2.9.1. The snap desktop-launcher fix therefore has a direct source
counterpart there; it still needs runtime validation. The 2.9.1 scrobbler service
has differences, so reassess the saved-queue startup fix when porting it.
